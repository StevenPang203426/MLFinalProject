# 强化学习中的奖励设计

## 项目概述

本项目旨在深入研究和实践强化学习（Reinforcement Learning, RL）中的奖励设计问题。强化学习通过奖励信号引导智能体学习最优策略，奖励函数的设计是RL系统成功的关键。然而，奖励设计也面临诸多挑战。

## 项目背景

### 奖励设计面临的挑战

1. **奖励黑客（Reward Hacking）**
   - 智能体会利用奖励函数的缺陷或模糊性来获得高奖励，但并未真正学习或完成预期任务

2. **稀疏奖励与延迟反馈**
   - 任务仅在完成时给予奖励，中间步骤无反馈
   - 例如：对话任务中，只在整个对话结束时评估，导致难以定位哪一轮回复出了问题

3. **多奖励权衡**
   - 当强化学习有多个奖励时，如何平衡这些奖励

4. **形式化困难**
   - 创意写作等任务没有标准答案，难以形式化奖励

## 项目任务

### 1. 调研主流奖励设计方法

调研至少3种主流奖励设计方法，包括但不限于：

- **RLHF（Reinforcement Learning from Human Feedback）**
  - 从人类反馈中学习奖励函数
  - 分析原理、优势、局限和适用场景

- **RLVR (Reward Verification / Verifiable Reward)**
  - 可验证奖励方法
  - 分析原理、优势、局限和适用场景

- **Direct Preference Optimization (DPO)**
  - 直接偏好优化方法
  - 分析原理、优势、局限和适用场景

- 其他新方法（可选）

### 2. 基线实验

#### 实验设置
- **框架选择**：使用 TRL 或类似框架（如 verl、slime、OpenRLHF）
- **模型选择**：选择小规模模型（推荐：Qwen-1.8B 等参数量 < 7B 的模型）
- **任务选择**：在一个具体任务上进行 RLHF 微调
  - 推荐任务：
    - TL;DR 摘要生成
    - GSM8K 数学推理任务
    - 其他合适的任务
- **可视化工具**：推荐使用 wandb 可视化训练指标

#### 实验要求
- 完成基线实验并记录实验结果
- 记录训练过程中的关键指标（loss、reward、生成质量等）

### 3. 奖励机制分析

#### 代码分析
- 阅读所选框架中 reward model 的实现（建议用 debug 的方式阅读代码）
  - 奖励计算方式
  - 奖励归一化策略（如有）
  - 奖励与策略更新的交互逻辑

#### 问题分析
分析现有实现的优劣：
- 是否存在 reward hacking 风险？
- 稀疏奖励问题如何处理？
- 奖励函数的设计是否合理？

### 4. 改进奖励实现

可以选择以下方向尝试改进：

#### 4.1 奖励正则化
- 添加约束防止 reward hacking
  - 长度惩罚
  - 重复惩罚
  - 其他正则化方法

#### 4.2 奖励塑形（Reward Shaping）
- 设计中间步骤的辅助奖励
  - 例如：摘要任务中的"相关性"、"简洁性"子奖励
  - 提供更细粒度的反馈信号

#### 4.3 多奖励权重平衡
- 如果涉及多个奖励，平衡多个奖励目标
  - 简洁性 vs 准确性
  - 其他多目标权衡

#### 4.4 更换奖励设计
- 如将 reward model 改为 verifier
- 尝试其他奖励设计方法

### 5. 对比分析与可视化

- **性能对比**：对比改进前后的性能变化
- **原因分析**：深入分析结果产生的原因
- **可视化工具**：推荐使用 wandb 可视化分析工具
- **实验记录**：鼓励大胆尝试，实验结果不是 SOTA 没关系，重要的是分析结果产生的原因
- **失败记录**：可以记录失败的尝试，分析失败原因
